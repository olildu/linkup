# Local Persistence Guide

> What is stored on-device, where it lives, and how to read/write it.

---

## Two storage layers

The app uses two completely different storage mechanisms for different purposes:

| Storage | Package | Used for |
|---|---|---|
| **Isar** | `isar` | Structured data — messages, chats, unsent message queue |
| **SharedPreferences** | `shared_preferences` | Simple key-value — theme mode, app lock flag |
| **FlutterSecureStorage** | `flutter_secure_storage` | Encrypted — JWT access token, refresh token, user ID |

Each has a different job. Never put tokens in SharedPreferences (it's not encrypted). Never put theme mode in Isar (overkill for a single boolean).

---

## Isar — structured local database

Isar is a fast NoSQL database. It stores objects that you define as Dart classes, with code-generated query and write APIs.

### Schema files

```
lib/data/isar_classes/
  message_table.dart        ← chat messages (per conversation)
  chats_table.dart          ← conversation list
  unsent_messages_table.dart  ← messages queued for sending (offline buffer)
```

Each file has a `.g.dart` sibling generated by Isar's code generator. **Never edit `.g.dart` files by hand.**

### The `MessageTable`

```dart
@collection
class MessageTable {
  Id id = Isar.autoIncrement;   // Isar's auto-incrementing row ID

  late String messageID;        // your own UUID (from the server)
  late String message;
  late int to;
  late int from_;
  late int chatRoomId;
  late bool isSeen;
  late bool isSent;
  late DateTime timestamp;
  String? mediaJson;            // JSON-encoded MediaMessageData (nullable)

  // Converts between Isar row and domain model
  MessageTable.fromMessage(Message msg) { ... }
  Message toMessage() { ... }
}
```

The `@collection` annotation marks this as an Isar collection (equivalent to a database table). Each `late` field becomes a column. The `mediaJson` field is a workaround — Isar doesn't store nested objects, so the media data is JSON-encoded into a string.

### Reading from Isar

```dart
// In a datasource
class MessageLocalDatasource {
  final Isar _isar;
  MessageLocalDatasource(this._isar);

  Future<List<Message>> getCachedMessages(int chatRoomId) async {
    final rows = await _isar.messageTables
        .where()
        .chatRoomIdEqualTo(chatRoomId)
        .sortByTimestampDesc()
        .findAll();
    return rows.map((r) => r.toMessage()).toList();
  }
}
```

Isar generates the `.where()` query builder from your schema. After running code generation, you get typed query methods for every field.

### Writing to Isar

```dart
Future<void> cacheMessage(Message message) async {
  await _isar.writeTxn(() async {
    await _isar.messageTables.put(MessageTable.fromMessage(message));
  });
}
```

All writes go inside `writeTxn`. Reads outside a transaction are fine.

### The `ChatsTable`

Stores the conversation list — who you're chatting with, the last message, unread count. Loaded on app start and updated as new messages arrive, so the connections screen shows fresh data even before the API responds.

### The `UnsentMessagesTable`

The offline buffer. When the user sends a message and the WebSocket is down:

1. The message is saved here first
2. The socket send is attempted (and fails silently)
3. When the socket reconnects, `ChatSocketsBloc` reads all rows from this table, resends them, then deletes each row on success

This table should normally be empty. If you see it growing, the socket is failing to reconnect.

## Running code generation

If you add or modify an Isar collection class, regenerate the `.g.dart` files:

```bash
# From the project root
fvm flutter pub run build_runner build --delete-conflicting-outputs
```

If the generated file is stale, queries will fail to compile.

## SharedPreferences — simple key-value

Used for non-sensitive, non-structured settings.

| Key | Type | Used in |
|---|---|---|
| `theme_mode` | String (`'light'` / `'dark'`) | `ThemeCubit` |
| `app_lock_enabled` | bool | `AppLockCubit`, `AuthRepositoryImpl` |

```dart
// Writing
final prefs = await SharedPreferences.getInstance();
await prefs.setString('theme_mode', 'dark');

// Reading
final saved = prefs.getString('theme_mode');
```

`SharedPreferences.getInstance()` is async but caches the instance after the first call, so subsequent calls are effectively synchronous.

## FlutterSecureStorage — encrypted key-value

Used only for JWT tokens. The data is encrypted by the OS keychain (Keychain on iOS, EncryptedSharedPreferences on Android).

| Key | Value |
|---|---|
| `access_token` | JWT access token |
| `refresh_token` | JWT refresh token |
| `user_id` | Logged-in user's ID |

Managed entirely by `TokenService`:

```dart
class TokenService {
  final FlutterSecureStorage _storage;
  TokenService(this._storage);

  Future<void> saveTokens({
    required String accessToken,
    required String refreshToken,
    required String userId,
  }) async {
    await _storage.write(key: 'access_token', value: accessToken);
    await _storage.write(key: 'refresh_token', value: refreshToken);
    await _storage.write(key: 'user_id', value: userId);
  }

  Future<void> clearTokens() async {
    await _storage.deleteAll();
  }
}
```

**Never read token storage directly from a widget or bloc.** Use `TokenService` or `CustomHttpClient` (which reads it internally). If you need the user ID in a widget, get it from the `ProfileBloc` state — not from secure storage.

---

## What gets cleared on logout

`AuthRepositoryImpl.logout()` calls:
1. `_tokenService.clearTokens()` — wipes secure storage (access token, refresh token, user ID)
2. `_clearAppLock()` — removes the `app_lock_enabled` SharedPreferences key

Isar is **not** cleared on logout. Message cache persists across logout/login cycles. If this ever becomes a privacy concern (multi-user device), add an Isar clear step to `logout()`.
